## Warning 口径

最终冻结验收记录为后端全量 `323 passed / 2696 warnings`，Q012—Q015 及 Q018 安全回归为 `241 passed / 2573 warnings`。材料应写“存在第三方兼容和项目内 UTC 时间 API 弃用 warnings”，不要把 warning 总数当作固定产品指标或生产质量无风险声明。

## 引用规则

1. 数字必须注明验证范围和日期。
2. “通过”只修饰实际运行的检查，不外推为全部质量、全部平台或生产可用。
3. mock、fallback、not_configured 必须与真实云调用明确区分。
4. RAG 指标必须同时写“5 条评价集”和“仅用于回归/演示”。
5. DKVMN 必须使用“轻量在线门控记忆知识追踪”，不得写“训练完成的深度模型”。
6. OpenAPI operation 数量只用于接口契约统计，不得改写为核心功能数量。
7. Docker 只能写“静态检查通过、动态未验证”；微信真机和未覆盖的人工 UI 必须标记为“尚未验证”。Python 3.11.9 干净 venv 后端复验和 Node 24.14.0 前端构建复验可按实际日志表述，不再要求 `py -0p` 成功或 Node 必须为 20。
8. 本地数据库记录数会随脚本运行变化，不作为固定知识库或用户规模。

## 禁止表述

- “系统全部测试无风险”
- “真实讯飞已验证”或“讯飞调用成功”（在未提供真实调用证据时）
- “大规模 RAG 准确率”
- “预训练 DKVMN 模型”
- “117 项核心功能”
- “Docker 动态部署/微信真机/全量三角色 UI 已全面通过”
- 任何来自旧包的 78 项测试或 8 类资源口径
